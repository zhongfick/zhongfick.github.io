*JDK动态代理

核心在于 Proxy 和 Invocationhandler 这两个类
继承Invocationhandler类，也就是说明这个类里面要抓对象做动态代理了

 static class LogInvocationHandler implements InvocationHandler

类本身有一个方法invoke，里面就是要写的增强方法

public Object invoke(Object proxy, Method method, Object[] args) throws Throwable

调用的时候创建对象创建handler，通过Proxy类的方法，例如

OrderService proxyService = (OrderService) Proxy.newProxyInstance(
                realService.getClass().getClassLoader(),
                realService.getClass().getInterfaces(), // 关键：只能代理接口
                handler);

Proxy创建代理对象，通过getclass.getclassloader获得类加载器
                  通过getclass.getInterfaces获得类实现的所有接口，java是单继承但可以实现多接口   （所以是“所有”）
                  handler就是创造出来的invocationhandler

*CGLIB
CGLIB用MethodInterceptor,JDK动态代理用Invocationhandler
     用Enhancer代替JDK动态代理里面的Proxy

CGLIB是当类的儿子，重写父类方法
JDK动态代理是继承类接口

 JDK 代理走反射调用，CGLIB 走字节码子类调用

1. 动态代理单独提取出来有没有意义？有，而且很常见
动态代理是一种通用的"方法调用拦截"机制，AOP 只是它的一个应用场景。独立用它的例子：

RPC 框架（如 Dubbo、Feign）：你注入的接口没有实现类，调用它时，动态代理在 invoke 里把"方法名 + 参数"序列化成网络请求发出去，拿到结果再返回。这里没有任何"增强原方法"的概念，原方法根本不存在，代理直接构造了行为。

MyBatis 的 Mapper 接口：UserMapper 没有实现类，动态代理在 invoke 里根据方法名拼 SQL、查数据库。也不是 AOP。

懒加载 / 延迟初始化：代理先不建真实对象，第一次调用时才创建。

访问控制 / 缓存：代理里判断权限或查缓存，命中就返回，不调原方法。

所以"生成代理对象没什么用"不成立——代理的核心价值是"在调用方和目标之间插一层，让你能控制这次调用"。AOP 只是"用这层插入增强逻辑"的其中一种用法。

2. 动态代理 = AOP 的一个过程吗？
更准确的说法是：动态代理是实现 AOP 的一种底层手段，但：

AOP 是"思想/目标"：把横切关注点（日志、事务）从业务代码抽离，统一织入。

动态代理是"实现手段"：生成代理对象来拦截方法调用。

AOP 不只能靠动态代理：AspectJ 用编译期/类加载期字节码织入，根本不生成运行时代理对象。所以"动态代理就是 AOP 的过程"这个说法把手段当成了本质。

3. 那"生成代理对象"到底在干嘛？
用一句话概括：代理对象让你在不改原对象代码的前提下，接管对它的调用。 接管之后你想干什么都行——

增强（AOP：加日志、事务）→ 调原方法前后插逻辑

替换（RPC / MyBatis：根本没有原方法）→ 代理自己实现行为

控制（权限、缓存、懒加载）→ 决定调不调、什么时候调

AOP 是"接管后增强"这一支，不是全部。
